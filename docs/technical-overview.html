TECHNICAL OVERVIEW

VLMAutoReplayTool 技術解説書

「計画(基盤モデル)」と「実行(専用モデル・スキル・API)」を分離したゲーム自動プレイエージェントの実装リファレンス。 設計の一次情報は VLMAutoReplayTool_DESIGN.md(Phase0〜7)。 本書はそれを現在のコード(src/)に即して説明する。Markdown版: TECHNICAL_OVERVIEW.md

1. 全体像

中核ループは capture → generate_next_action → execute → 状態変化確認 → repeat という単純な形を保ち、各ステップの行動理由(reasoning)を必ず記録する。

アーキテクチャ境界(最重要): generate_next_action を含む prompts/functions.py は knowledge.rag_client を一切importしない。1ステップの実行サイクルではRAG呼び出しが物理的に0回になる(tests/test_rag_boundary.py でAST静的解析により実証)。

4. Phase2: MainLoop + StepLog

sequenceDiagram
    participant MainLoop as MainLoop.run()
    participant Cap as ScreenCapture
    participant FM as FoundationModelClient
    participant Exec as ActionExecutor
    participant WD as Watchdog
    participant Sink as StepLogSink

    loop 1ステップ
        MainLoop->>Cap: capture()
        Cap-->>MainLoop: observation(before)
        MainLoop->>FM: generate_next_action(todo, obs, history)
        FM-->>MainLoop: NextActionOutput
        MainLoop->>FM: explain_action_choice(action, context)
        FM-->>MainLoop: reasoning
        MainLoop->>Exec: execute(action)
        MainLoop->>Cap: capture()
        Cap-->>MainLoop: observation(after)
        MainLoop->>FM: summarize_screen_change(before, after)
        FM-->>MainLoop: resultObservationSummary
        MainLoop->>Sink: log_step(StepLog)
        MainLoop->>WD: should_intervene(todo, logs)
        alt 介入すべき
            WD-->>MainLoop: true
            MainLoop->>MainLoop: break
        else 継続
            WD-->>MainLoop: false
        end
    end

StepLogは7フィールドを毎ステップ非nullで持つ。固定ディレイに依存せず、resultObservationSummaryの生成後にのみ進行判定を行う(main_loop.pyにsleep呼び出しは存在しない)。

9. GUIダッシュボード

src/vlm_auto_replay/gui/はコアエンジンをブラウザから操作するFastAPI製ローカルWebアプリ。既定で決定的なDemoModelClient/DemoGameを使うため、APIキーやドライバなしで即座に動作する。

sequenceDiagram
    participant Browser
    participant API as FastAPI
    participant State as RuntimeState
    participant Thread as バックグラウンドスレッド
    participant MainLoop

    Browser->>API: POST /api/todo/decompose
    API->>State: decompose(goal)
    State-->>API: todos
    API-->>Browser: todos(JSON)

    Browser->>API: POST /api/run/start
    API->>State: start_run(todoId)
    State->>Thread: Thread(daemon)
    Thread->>MainLoop: MainLoop.run(todo)
    loop ステップごと
        MainLoop->>State: log_step(log)へappend
    end

    loop 1.2秒ごと
        Browser->>API: GET /api/status
        API-->>Browser: snapshot(JSON)
    end

    Browser->>API: POST /api/run/stop
    API->>State: stop_run()

フロントエンドはVLMAutoReplayTool_UI_DESIGN.md(Sentri風トークン)に準拠: ダークキャンバス、lime強調チップ、Rubikフォント。

9.1 APIエンドポイント一覧

メソッド/パス内容
GET /api/statusstatus/progress/stepsToWin/todos/logs/skills/watchdogThresholdのスナップショット
POST /api/todo/decomposegoal → decompose_goal_to_todoでTODO生成
POST /api/run/starttodoId+maxSteps → MainLoop.runをバックグラウンド実行
POST /api/run/stop次ステップ末尾で停止させる
GET /api/observation/{ref}StepLogのサムネイル画像(SVG)を返す
POST /api/skillsgameTitle+proceduralText → procedureスキルを追加
DELETE /api/skills/{skillId}スキルライブラリから削除
GET /api/history過去の実行(SQLite永続化)の一覧をstartedAt降順で返す
GET /api/history/{runId}特定Runのメタデータ+全StepLog
GET /api/settings現在のHIDバックエンド設定(current/error/options)
POST /api/settings/hid-backendname(none/sendinput/vigem) → Phase3の実HID実装を構築して切り替え

進捗の可視化: DemoGame.progress/steps_to_winをRuntimeStateが実行中インスタンス経由で公開し、フロントエンドがプログレスバーとして描画する。

画像プレビュー: 観測バイト列はRuntimeState.observationsに保存され、/api/observation/{ref}がrender_observation_svg()でサムネイルSVGへ変換して返す。実運用で実キャプチャに差し替えた場合は、このエンドポイントがバイト列をそのまま返すだけでよい構造。

セッションの永続化(gui/persistence.py::SqlitePersistence): スキルライブラリと実行履歴をSQLite(~/.vlm_auto_replay/gui.sqlite3)に永続化し、サーバー再起動後も残る。skills/runs/run_logsの3テーブルのみで、マイグレーション機構は持たない。

Watchdog介入・TODO再構築の可視化: 通常のデモ実行は閾値(既定8)に達する前に完了するため介入が自然には見えない。stallDemo: trueで意図的に完了しないDemoGameを使い、介入とrebuild_todo()による再構築を確実に発生させ、結果をlastInterventionとしてバナー表示する。

HIDバックエンド選択: RuntimeState.set_hid_backend()はPhase3のApiPrimitivesを実際に構築し直す(none→Null、sendinput→SendInputBackend、vigem→ViGEmPadBackend)。構築失敗時(未インストール/非Windows等)は422を返し設定は変更しない。デモ実行フロー(DemoGame)はHIDを経由しないため、この設定はStepLogの挙動には影響しない — この環境でPhase3の実装が構築できるかの確認と、実運用差し替えの起点を提供する。
